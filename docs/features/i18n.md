# Internationalization (i18n)

> Users can switch the interface between English, Italian and Ukrainian via a
> dropdown in the header; every translated string, date and number follows the
> chosen locale.

**Status:** Shipped
**Added:** 2026-08
**Code:** `apps/web/app/[locale]/layout.tsx`, `apps/web/src/components/shared/LocaleSwitcher/`, `apps/web/messages/`

---

## Behaviour

The app renders under a URL prefix (`/en`, `/it`, `/uk`). On first visit the
locale is auto-detected from the browser's `Accept-Language` header; subsequent
visits remember the last choice.

A **LocaleSwitcher** dropdown sits in the header, before the theme toggle. It
shows the active locale code and a flag-inspired corner triangle. Opening it
lists all supported locales with their endonyms (English, Italiano, Українська).
Selecting a locale replaces the URL prefix without reloading data or resetting
scroll position.

All user-visible strings come from JSON message files. Dates, numbers and
relative times are formatted via `useFormatter()` from next-intl.

## URL state

| Segment | Values | Default | Meaning |
| --- | --- | --- | --- |
| `[locale]` | `en` \| `it` \| `uk` | `en` | Interface language |

## Implementation notes

**Library:** next-intl v4 with App Router URL-prefix routing.

**Layout structure:** `app/[locale]/layout.tsx` owns `<html>`, `<body>`,
`NextIntlClientProvider` and font loading. There is no root `app/layout.tsx` —
the `[locale]` segment is the true root, so every client component receives the
locale from the provider without a separate context.

**QueryClient singleton:** the layout remounts on locale change (new `params`).
A module-scoped `QueryClient` singleton (the official TanStack pattern for App
Router) survives the remount, preventing data refetch.

**Scroll preservation:** `router.replace(pathname, { locale, scroll: false })`
keeps the user's scroll position.

**Non-modal dropdown:** `RadixDropdown.Root` is set to `modal={false}`. The
default modal mode locks body scroll and adds compensating padding, which
conflicts with the global `scrollbar-gutter: stable` and causes a visible page
jump.

**Layout stability across locales:** translations vary in length. The components
that are most affected use fixed widths or minimum widths to prevent layout
shift: the locale switcher trigger has a fixed-width code slot (`w-6`), filter
pills have `min-w-24`/`min-w-30`, the musical key column is 104 px wide with
`truncate`, and nav tabs use `grid auto-cols-fr` with `w-fit` for equal-width
shrink-wrapping.

**Fonts and Cyrillic:** Spectral (prose) includes a Cyrillic subset. Alfa Slab
One, Oswald and Space Mono are Latin-only with explicit system fallback stacks.

## Translation files

Three namespace files in `apps/web/messages/{en,it,uk}/`:

| File | Scope |
| --- | --- |
| `common.json` | Navigation, shared buttons, general UI |
| `auth.json` | Login, signup, auth errors |
| `pages.json` | All page-specific content, grouped by feature |

Keys use camelCase, sorted alphabetically at every level, max nesting depth of
2. English is the source of truth; Italian and Ukrainian must mirror the key set
exactly.

## Edge cases

- Missing translation key: next-intl logs a warning and renders the key path.
- Unknown locale in URL: middleware redirects to the default (`en`).
- Unprefixed protected path without a token: middleware parses
  `Accept-Language` to pick the login-page locale, falling back to `en`.
- Cyrillic in Latin-only fonts: falls back to the system font stack
  transparently.
